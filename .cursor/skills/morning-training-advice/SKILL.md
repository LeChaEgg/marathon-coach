# 晨间训练建议

## 流程

1. 运行晨报（会先增量同步；需要网络，Shell 调用时申请 `full_network`）：
   ```bash
   python3 -m coach today
   ```
   同步失败时报告会写明原因，并改用缓存。先按 AGENTS.md 排查网络和认证，不要把失败当成“没有数据”。
2. 阅读报告，并读取本周计划 `plan/weeks/<本周>.md`（报告第 5 节已摘出今天的条目；文件不存在时参考 `plan/season_plan.md` 中本周那一行）。
3. 看用户在消息里是否说了今天的主观状态（胫骨/跟腱等疼痛、腿沉、精神、昨晚睡眠感受）。如果说了，先用 `python3 -m coach log --date <今天> --pain N --pain-loc ... --note ...` 记下来。
4. 按优先级判断：局部胫骨疼痛/跳跃痛/跛行 > 主观疲劳与次日反应 > 最近跑量（尤其是 7 天/此前周均比值）> wellness 偏离 > VO₂max。报告第 6 节的红绿灯只是客观信号初判。
5. 给出今日处方（格式见下）。用户没提疼痛时，不要停下来追问：直接给处方，把“胫骨无痛”写成执行前提，并列出有疼痛时的替代方案。
6. 把结论追加到 `reports/daily/<日期>.md` 末尾，标题固定为 `## 教练结论`（脚本重跑时会保留这一节）。
7. 结论写入报告文件后，训练中心网页（`python3 -m coach serve`）的「今日」页会自动显示，不需要再运行任何命令。

## 判断要点

- 前一天是长距离或质量课 → 今天默认恢复/休息，除非计划另有安排且各项指标良好。
- 跑量比值 >1.5，或连续跑步 ≥5 天 → 优先减少冲击：缩短距离、换软地面，或改骑行。
- HRV 低于基线 2SD，或静息心率连续两天偏高 → 取消质量课，改 Z1 轻松跑或休息。
- 单一指标偏离（比如只有睡眠短）→ 质量课可以保留，但缩短主体或放宽配速。
- 报告第 6 节末尾写了当前计划激进程度，以及客观黄灯时对应的处理（1–3 档取消质量课并减量，4 档取消质量课、少减量，5 档保留缩短的质量课）。只有负荷和 wellness 信号按档位处理；疼痛信号不看档位。
- 胫骨疼痛 3/10 或在上升 → 黄：取消质量课、减量 20–40%、平路软地面；出现骨性压痛/跳跃痛/跛行 → 红：停跑，建议运动医学评估。
- 质量课的配速给范围，同时给心率上限；天热时按心率执行。
- 心率区间：Z1 ≤147，Z2 148–156，Z3 157–163，Z4 164–172，Z5 173–177。

## 输出格式

```markdown
**今日结论：🟢 按计划 / 🟡 调整 / 🔴 停跑** — 一句话说明

**训练处方**
- 类型与目的：……
- 结构：热身 …｜主体 …｜放松 …
- 强度：心率 ≤…（或区间 …），配速参考 …/km
- 附加：加速跑 / 力量 / 拉伸（如适用）

**依据**
- 恢复（API 观察值 vs 28 天基线）：……
- 负荷：……
- 计划位置：……（本周第几次课、明天安排什么）

**执行中调整**：如果出现 X → 改为 Y（包括疼痛的退出条件）

**跑后请反馈**：实际距离/时间、RPE、跑中/跑后疼痛及位置、步态是否改变、异常疲劳、补给
```

API 观察值、用户主观反馈和既有基线要分开写。没有今天的 wellness 数据时要写明，不能用历史数据冒充。

- 当天是质量课或长距离时，建议里要重复计划里的“证据设计”要点（例如阈值课必须连续 ≥13 分钟留在 HR 157–177），让这节课能产生评分证据。
